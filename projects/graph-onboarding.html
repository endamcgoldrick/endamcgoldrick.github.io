Graph onboarding scripts

The problem

Joiners and leavers follow the same steps every time. In: create the account, set the usage location, assign a licence, add the groups. Out: block sign-in, end the sessions, remove groups and licences. Done by hand, a step gets missed, and a missed step on the way out is a leaver who still has access.

I did this work in my last job. I wanted to write the same process as a script that can be checked before it runs and leaves a record of what it did.

What I built

Four scripts:

  • New-OnboardUser.ps1 reads a CSV, creates each user, sets the usage location, assigns a licence by its SKU part number and adds the group memberships.
  • Invoke-OffboardUser.ps1 blocks sign-in, revokes sessions, removes group memberships and licences, and records what it did.
  • Get-InactiveUsers.ps1 writes a CSV of accounts that have not signed in for a set number of days.
  • Get-MfaStatusReport.ps1 writes a CSV showing who has MFA methods registered.

How I built it

  • Sign-in is interactive only (Connect-MgGraph). There are no stored secrets.
  • Each script asks for the smallest set of Graph permissions it needs. The README has a table of them.
  • Every script that changes something supports -WhatIf, so you can see what it would do first.
  • Passwords are never printed or written to a log.
  • The logic that doesn't need a tenant is covered by Pester tests, and the code is checked with PSScriptAnalyzer.
  • The sample CSV uses obviously fake people.
