The problem

I am working towards the AZ-104 exam. I have not passed it yet. Reading about virtual networks, backup and monitoring is not the same as setting them up and watching them fail.

I wanted a lab that is defined in code, so it can be created the same way each time and removed with one command when I am done.

What I built

Bicep files for:

  • a resource group and a virtual network,
  • one small Windows Server VM with an auto-shutdown schedule,
  • a Log Analytics workspace with a couple of alert rules,
  • a Recovery Services vault with a backup policy.

Around the Bicep there is a parameters file with placeholders, a cost note, a teardown script, and a written runbook for promoting the server to a domain controller and setting up hybrid identity with Entra.

How I built it

The Bicep is checked with bicep build and the linter. Values that identify a subscription or tenant are placeholders in a parameters file, so none are in the repository.

The domain controller and hybrid identity steps are written as a runbook, not as code, because they are done by hand on the server.
