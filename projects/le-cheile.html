Le Chéile

A calendar for two people: a private one each, and a shared one you both edit.

Personal project
Built for me and one other person to use every day
In use
Live and still changing
Stack
JavaScript, Firebase Authentication, Cloud Firestore, Firebase Hosting, GitHub Actions
Code
In a private repository

The problem

Two people share a life but not every plan. I wanted a calendar where each of us keeps our own, there is one shared calendar we both edit, and we can see when the other is busy without seeing why.

It had to work on both our phones, open fast, and be private to the two of us.

What I built

  • Google sign-in, limited to two accounts.
  • A private calendar each, and a shared calendar that either person can edit.
  • Linking by a 6-character invite code that expires after 7 days.
  • Busy times without the details, unless you choose to show titles.
  • A warning when plans clash, and a "find a time together" view.
  • Weekly hour goals with suggested time blocks.
  • Read-only Google Calendar sync, with permission, and a saved copy so the agenda shows straight away.
  • Schedule, Day, Week and Month views with swipe on a phone, and tick boxes to mark events done.
  • It installs on a phone and keeps working offline.

How I built it

It is plain JavaScript with no framework and no build step. Firebase handles sign-in, the database and hosting. Every push to the main branch is published by a GitHub Actions workflow. It checks the code before publishing and the live site's security headers afterwards.

Privacy is enforced in the database, not only on screen. The security rules allow only the two accounts, keep each private calendar readable by its owner alone, and let a shared event be read and edited only by its two members.

What I'd do differently

  • I would design the phone layout first. My first version was a desktop calendar squeezed onto a phone, and it felt cramped on a real handset. Schedule, Month and swipe came later and fixed it.
  • I would set the page's cache headers on day one. For a while a phone kept showing an old copy of the page next to the new code, which looked like a bug in the new views.
  • I would check the platform limits before promising a feature. Reminders when the app is closed need a scheduled server job, which Firebase only runs on a paid plan. I chose not to pay for it, so reminders work while the app is open or in the background.
